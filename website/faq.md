# 常见问题

## 连不上、找不到设备

| 现象 | 先看这里 |
| --- | --- |
| 设备列表一直是空的 | 两台防火墙是否放行「专用网络」；是否**都停在文件共享页**；是否在同一个网段 |
| 本机地址看着不对 | 多半是虚拟网卡的段。程序只认物理网卡，仍不对就看日志里 `LAN discovery` 那几行 |
| 手填 IP 也连不上 | 还是防火墙。两台都要放行，只放行一边不够 |
| 隔着 VPN 找不到对方 | 设计如此。发现层只走有线和无线物理网卡，不走 Tailscale 这类虚拟网卡 |
| 配对码输了对不上 | 配对码 5 分钟过期，过期就重新生成一个再输 |

## 屏幕切不动

| 现象 | 先看这里 |
| --- | --- |
| 点了切换屏幕没反应 | 在显示器 OSD 菜单里确认 DDC/CI 已开启；卡片上标「DDC不可用」说明这台显示器不响应写入 |
| 切完显示「未知输入源」 | 输入源刚切完的一瞬间 DDC 可能读到瞬时值，过一会儿会自己校正 |
| 切过去是错的口 | 不同品牌型号的 VCP 0x60 取值不一样，点「学习输入源」重新认一遍；学习结果按每台显示器独立保存 |
| 换了接线之后全乱了 | 同样点「学习输入源」；或者删掉 `DeskHoper-config/monitors.json` 恢复默认 |

## 键鼠和文件

| 现象 | 先看这里 |
| --- | --- |
| 键鼠转发失效 | 被控端弹了 UAC 提权窗，或目标窗口以管理员身份运行——普通权限进程注入不进去，页面上会显示错误 |
| 鼠标发飘、手感带曲线 | 对面关掉「提高指针精确度」，它的非线性曲线会叠加在转发位移上 |
| 想立刻夺回键鼠 | `Ctrl + Alt + Q` |
| 传文件报上限 | 单次 200 个文件、总量 512 MB，超了不会开始发送 |
| 复制文件没发出去 | 这是有意的。只有**拖进拖放区**才发送，避免本机拷一份时误发 |

## 已知限制

- 没有无界面模式：软件开着才生效，退出后剪贴板、文件、键鼠共享全部停止。
- 一次只支持两台机器，一对一。
- UAC 提权弹窗和以管理员身份运行的窗口注入不进去。
- 显示器不响应 DDC/CI 时只能读不能切。
- 局域网发现不能跨网段。
- 当前主要在 AOC 显示器环境下开发和测试，实际支持情况取决于显示器型号、连接方式、显卡驱动和固件。

## 运行环境

- Windows 10 / 11，x64
- 支持 DDC/CI 的外接显示器，并且显示器 OSD 菜单里已开启 DDC/CI
- 文件共享和键鼠共享需要两台机器在同一个局域网内
- self-contained 发布包不需要安装 .NET Runtime；如果你从源码跑，需要 .NET 8 SDK

## 从源码跑和提改动

```powershell
dotnet build DeskHoper.sln
dotnet run --project DeskHoper.Tests/DeskHoper.Tests.csproj -c Debug
dotnet publish DeskHoper.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o publish\vX.Y.Z-win-x64
```

回归测试是独立的控制台工程，不依赖测试框架，8 组契约测试覆盖投影模式、逐台 Profile、输入源学习、配对与加密链路、文件传输与接收路径安全、键鼠转发闸门和网卡筛选。屏幕切换相关的改动需要一台真机加支持 DDC/CI 的外接显示器才能验证，纯代码评审测不出来。

## 还是没解决

先看 `DeskHoper-config/logs/` 里当天的日志，收发、配对、DDC 读写结果都会记录。带上日志和「哪台机器、什么接线、点了什么」到仓库开 issue：<https://github.com/zhengnan365/DeskHoper/issues>。
