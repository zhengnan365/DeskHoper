# 网络与安全

## 端口

| 项 | 值 |
| --- | --- |
| 数据通道 | TCP `47810` |
| 局域网发现 | UDP `47811` |
| 加密 | TLS，自签证书并 pin SHA-256 指纹 |
| 配对 | 首次信任（TOFU），配对码一次性有效，5 分钟过期 |
| 中转 | 无。不经任何第三方服务器，数据只在两台机器之间直连 |

首次监听会弹 Windows 防火墙授权框，**两台机器都要放行「专用网络」**。已经拒绝过的话，去「控制面板 → Windows Defender 防火墙 → 允许应用通过防火墙」里把 DeskHoper 的专用网络勾上。

## 只走物理网卡

本机地址和发现层的收发都限定在有线、无线这两类网卡上。

Tailscale、Hyper-V、VMware 这类虚拟网卡各自编了一个内网段，对面拿那个地址回不来，所以它们既不会被当成本机地址显示，也不会出现在设备列表里。这也是为什么两台机器隔着 VPN 组网时不能靠发现层自动找到对方——那是设计如此，不是坏了。

## 传输限制

- 一次最多 200 个文件、总量 512 MB，超了不会开始发送，页面上会直接说原因。
- 局域网发现用 UDP 广播，**不能跨网段**。两台不在同一个网段时，先确认网络拓扑，或者换到有路由的网卡段；发现不了就在「我连接对方」里手填对面的名称或 IP。

## 数据会碰到什么

| 能力 | 走网络的内容 |
| --- | --- |
| 剪贴板文本 | 你复制的文本，明文进 TLS 隧道 |
| 文件传输 | 你拖进拖放区的文件字节 |
| 键鼠转发 | 键盘按键和鼠标位移、按钮状态 |
| 局域网发现 | 本机名称、数据端口号，UDP 广播 |

程序不收集、不上传任何使用数据，也没有账号和遥测。日志只写在本地 `DeskHoper-config/logs/`，记录收发、配对和 DDC 读写的结果，用于排查。

## 威胁模型说清楚

- 配对码是首次信任的一环：只有输对码才会把对方指纹记进 `peer.json`，之后直连只认这个指纹。
- 同网段的主机可以往发现端口伪造广播，最坏结果是列表里多出一条假设备；点它并输错配对码连不上。
- 已经配好对之后，链路上换证书会因指纹不匹配被拒。
- 键鼠转发会拦截本机输入。被控端弹 UAC 提权窗或以管理员身份运行的窗口，普通权限进程注入不进去，这时转发失效（页面上能看到错误），用 `Ctrl + Alt + Q` 交回。

## 代码可审计

项目全开源，网络层在 `Code/Services/Peer/`：`PeerLink.cs`（连接与帧收发）、`FrameCodec.cs`（帧编解码）、`LanDiscovery.cs`（发现层）、`PeerIdentity.cs`（证书与指纹），网卡筛选在 `Code/Services/PhysicalNetwork.cs`。配对与加密链路有独立的契约测试覆盖。
